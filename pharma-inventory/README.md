# คลังยา — ระบบบริหารคลังยาและเวชภัณฑ์ (Demo)

เว็บแอปสาธิตครบ 10 ฟังก์ชันตามภาพ infographic:
Dashboard, ข้อมูลยา, รับยาเข้า, จ่ายยาออก (FEFO), Lot & Expire, ตรวจนับสต็อก,
รายงาน, แจ้งเตือน, ผู้ใช้งานและสิทธิ์, ความปลอดภัย (Audit Log + สำรองข้อมูล)

เป็นเว็บ **static site** (HTML/CSS/JS ล้วน ไม่มี backend) เก็บข้อมูลไว้ใน
`localStorage` ของเบราว์เซอร์ผู้ใช้แต่ละคน — จึงสามารถขึ้นบน **GitHub Pages**
ได้ฟรี 100% โดยไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องตั้งค่าฐานข้อมูล

> ⚠️ ข้อจำกัด: เพราะเป็น static site ข้อมูลจะ**อยู่แค่ในเบราว์เซอร์ของแต่ละเครื่อง**
> ไม่ sync ข้ามอุปกรณ์ / ไม่มีระบบล็อกอินจริง เหมาะสำหรับสาธิต, ทดลองใช้งาน,
> หรือเป็นจุดเริ่มต้นก่อนต่อยอดเป็นระบบจริง (ดูหัวข้อ "ต่อยอดเป็นระบบจริง" ด้านล่าง)

## ไฟล์ในโปรเจกต์

```
pharma-inventory/
├── index.html   → โครงหน้าเว็บ
├── style.css    → ดีไซน์ทั้งหมด
├── script.js    → ตรรกะระบบ (state, FEFO, alerts, audit log)
└── README.md    → ไฟล์นี้
```

## วิธีที่ 1: ดูผลลัพธ์ในเครื่องตัวเองก่อน (ไม่บังคับ)

ดับเบิลคลิกไฟล์ `index.html` เปิดด้วยเบราว์เซอร์ได้เลย ไม่ต้องติดตั้งอะไร
(หรือถ้าต้องการรันผ่านเซิร์ฟเวอร์เล็ก ๆ ในเครื่อง ใช้คำสั่ง `python3 -m http.server`
ในโฟลเดอร์นี้แล้วเปิด `http://localhost:8000`)

## วิธีที่ 2: ขึ้นเว็บผ่าน GitHub Pages (ฟรี ไม่ต้องมีเซิร์ฟเวอร์)

### ขั้นตอนที่ 1 — สมัคร/ล็อกอิน GitHub
ไปที่ https://github.com แล้วสมัครบัญชี (ถ้ายังไม่มี)

### ขั้นตอนที่ 2 — สร้าง Repository ใหม่
1. คลิกปุ่ม **+** มุมขวาบน → **New repository**
2. ตั้งชื่อ เช่น `pharma-inventory`
3. เลือก **Public** (จำเป็นสำหรับ GitHub Pages แบบฟรีในบัญชีทั่วไป)
4. **ไม่ต้อง** ติ๊ก "Add a README file" (เพราะเรามีไฟล์ของเราเองแล้ว)
5. กด **Create repository**

### ขั้นตอนที่ 3 — อัปโหลดไฟล์ 3 ไฟล์
วิธีง่ายที่สุด (ไม่ต้องใช้คำสั่งใด ๆ):
1. ในหน้า repository ที่สร้างเสร็จ คลิก **"uploading an existing file"**
   (หรือปุ่ม **Add file → Upload files**)
2. ลากไฟล์ `index.html`, `style.css`, `script.js` ทั้ง 3 ไฟล์ ไปวางในหน้านั้น
3. เลื่อนลงมาด้านล่าง ใส่ข้อความ commit เช่น `initial commit`
4. กด **Commit changes**

> 💻 ถ้าถนัดใช้ Git/Terminal มากกว่า ให้ทำแบบนี้แทน:
> ```bash
> git init
> git add index.html style.css script.js README.md
> git commit -m "initial commit"
> git branch -M main
> git remote add origin https://github.com/<ชื่อผู้ใช้ของคุณ>/pharma-inventory.git
> git push -u origin main
> ```

### ขั้นตอนที่ 4 — เปิดใช้งาน GitHub Pages
1. ในหน้า repository ไปที่แท็บ **Settings** (บนสุด)
2. เมนูซ้าย เลือก **Pages**
3. ในหัวข้อ **Build and deployment → Source** เลือก **Deploy from a branch**
4. ที่ **Branch** เลือก `main` และโฟลเดอร์ `/ (root)` → กด **Save**
5. รอประมาณ 1–2 นาที ระบบจะสร้างลิงก์เว็บให้ที่ด้านบนของหน้าเดียวกัน
   รูปแบบ:
   ```
   https://<ชื่อผู้ใช้ของคุณ>.github.io/pharma-inventory/
   ```
6. เปิดลิงก์นี้ในเบราว์เซอร์ — เว็บของคุณพร้อมใช้งานแล้ว 🎉

### ขั้นตอนที่ 5 — อัปเดตเว็บในอนาคต
ทุกครั้งที่แก้ไฟล์แล้วอัปโหลดใหม่ (หรือ `git push`) GitHub Pages จะ deploy
เวอร์ชันใหม่ให้อัตโนมัติภายในไม่กี่นาที ไม่ต้องตั้งค่าซ้ำ

---

## การใช้งานระบบ

- ข้อมูลตัวอย่าง (ยา 5 รายการ, ล็อต, ผู้ใช้งาน) ถูกสร้างให้อัตโนมัติในครั้งแรก
- ปุ่ม **"ล้างข้อมูลตัวอย่าง"** ที่แถบด้านซ้ายล่าง ใช้รีเซ็ตกลับไปเป็นข้อมูลตั้งต้น
- เมนู **10 · ความปลอดภัย** มีปุ่ม **สำรองข้อมูล (JSON)** และ **กู้คืนจากไฟล์**
  สำหรับย้ายข้อมูลข้ามเครื่อง/เบราว์เซอร์ เพราะข้อมูลไม่ได้ sync กันอัตโนมัติ
- เมนู **04 · จ่ายยาออก** จะตัดสต็อกจากล็อตที่ **หมดอายุก่อน** โดยอัตโนมัติ (หลัก FEFO)
- เมนู **07 · รายงาน** ส่งออกไฟล์ CSV (เปิดได้ด้วย Excel) ได้ 3 แบบ: คงเหลือ,
  รับ-จ่าย, และ Lot/วันหมดอายุ

## ต่อยอดเป็นระบบจริง (ถ้าต้องการใช้งานในหน่วยงาน/โรงพยาบาลจริง)

เวอร์ชันนี้เหมาะกับการสาธิต/ทดลองแนวคิด แต่การใช้งานจริงในหน่วยงานควรมี:

- **ฐานข้อมูลฝั่งเซิร์ฟเวอร์** (เช่น PostgreSQL/MySQL) แทน localStorage เพื่อให้
  ข้อมูล sync ระหว่างผู้ใช้และอุปกรณ์ทุกเครื่อง
- **ระบบล็อกอิน/ยืนยันตัวตนจริง** พร้อมการเข้ารหัสรหัสผ่าน และสิทธิ์การใช้งาน
  (role-based access control) ที่บังคับใช้ฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่ UI
- **Audit Log ที่เก็บฝั่งเซิร์ฟเวอร์** ป้องกันการแก้ไข/ลบย้อนหลัง
- HTTPS + การสำรองข้อมูลอัตโนมัติ

GitHub Pages รองรับเฉพาะไฟล์ static เท่านั้น หากต้องการ backend จริง แนะนำ
บริการอย่าง Render, Railway, Vercel (สำหรับ API), หรือ Supabase/Firebase
สำหรับฐานข้อมูลและระบบล็อกอิน แล้วให้หน้าเว็บนี้เรียก API แทนการอ่าน/เขียน
